L2（トランク・EtherChannel・STP）

802.1Q・DTP ネイティブ VLAN on・PAgP・LACP Rapid PVST+・MST ルートガード・BPDU ガード

ENCOR の「インフラ」分野のうち、L2 で問われるのは次の3つ。どれも「設定して、show で確かめ、おかしければ直す」までできるようにする。

テーマ出題のポイント

EtherChannel手動（on）、PAgP、LACP で束ねる。束ならないときの切り分け

1. VLAN とトランク

何のための技術か

  • VLAN：1台のスイッチの中を、別々のブロードキャストドメインに分ける
  • トランク：1本のリンクで複数の VLAN のフレームを運ぶ。どの VLAN のフレームかは、802.1Q のタグで見分ける

802.1Q のタグ

項目内容
VLAN ID の範囲1〜4094（標準範囲 1〜1005、拡張範囲 1006〜4094）
ネイティブ VLANトランクでタグを付けずに送る VLAN。既定は VLAN 1。両端で一致させる（次の節）
許可 VLANトランクで運ぶ VLAN の一覧。既定はすべて

ネイティブ VLAN

トランクでは、ふつうはフレームに VLAN のタグを付けて運ぶ。ただし 1つの VLAN だけはタグを付けずに送る。これがネイティブ VLAN。

トランクで受け取ったフレームどの VLAN として扱うか
タグ付き（VLAN 20 など）タグに書いてある VLAN
タグなしネイティブ VLAN（既定は VLAN 1）

両端で一致させる理由：違っていると、別の VLAN にフレームが漏れる。

ネイティブ VLAN を VLAN 1 のままにせず、使わない VLAN（例：99）に変える理由

理由内容
VLAN 1 には、何もしなくても端末が入っているすべてのポートは最初から VLAN 1。設定し忘れたポートや空いているポートにつないだ PC も、VLAN 1 に入る
二重タグの攻撃を防ぐ攻撃者がタグを2枚重ねたフレームを送ると、1台目のスイッチが外側のタグ（ネイティブ VLAN）を外し、2台目が内側のタグを読むので、別の VLAN に入り込める。攻撃者がネイティブ VLAN の中にいることが条件なので、ネイティブ VLAN をどのアクセスポートにも割り当てない VLAN にすれば防げる
VLAN 1 は何にも使わないのが定番VLAN 1 は削除できず、CDP・DTP・VTP・PAgP などの制御用のフレームも VLAN 1 で送られる。利用者の通信を混ぜない

99 という番号に意味はない。どのアクセスポートにも割り当てていない VLAN であればよい。ネイティブ VLAN にもタグを付ける vlan dot1q tag native（グローバル設定）もある。使わないポートは shutdown し、使わない VLAN（例：999）に入れておく。

「VLAN 1」はネットワーク（ポートの集まり）で、ループバック（どのネットワークにも属さない、機器の中だけのインタフェース）とは関係ない。interface Vlan1 は、VLAN 1 の中に置いたスイッチ自身のインタフェース（SVI）。

設定例

vlan 10   ! VLAN を作る
 name SALES   ! 名前は任意
vlan 20
 name DEV
!
interface GigabitEthernet1/0/1
 switchport mode access   ! アクセスポートに固定（DTP を使わない）
 switchport access vlan 10   ! VLAN 10 に入れる
!
interface GigabitEthernet1/0/24
 switchport trunk encapsulation dot1q   ! ISL にも対応した一部の機種でだけ必要
 switchport mode trunk   ! トランクに固定
 switchport trunk native vlan 99   ! ネイティブ VLAN を使わない VLAN にする
 switchport trunk allowed vlan 10,20,99   ! 運ぶ VLAN を決める
 switchport nonegotiate   ! DTP を止める

許可 VLAN をあとから足すときは switchport trunk allowed vlan add 30。add を忘れると、一覧が 30 だけに置き換わり、それまで通っていた VLAN が止まる。

DTP：トランクを自動で組むしくみ

DTP は Cisco 独自の、トランクにするかどうかを相手と自動で決めるプロトコル。両端のモードを選ぶと、どうなるかが分かる。

モード動き
access常にアクセスポート
trunk常にトランク（DTP も送る）
dynamic desirable自分からトランクにしようと働きかける
dynamic auto相手から誘われたらトランクになる（自分からは誘わない）

DTP を動かしたままにすると、攻撃者の PC がスイッチのふりをしてトランクを組み、すべての VLAN に入れてしまう（VLAN ホッピング）。ポートは access か trunk に固定し、トランクには nonegotiate を付けるのが基本。

点線の付いたところにポインタを当てる（スマホは押す）と、意味が出る。

Port        Vlans allowed on trunk

Gi1/0/24    10,20,99

  • show interfaces Gi1/0/24 switchport：Administrative Mode（設定したモード）と Operational Mode（実際の状態）を比べられる
  • show vlan brief：VLAN とアクセスポートの一覧。トランクのポートはここに出ない

2. EtherChannel

何のための技術か

複数の物理リンクを1本の論理リンク（Port-channel）に束ねる。帯域が増え、1本が切れても通信が続く。

振り分けはフロー（通信）ごと（送信元・宛先のアドレスなどのハッシュ）。1つの通信が2本に分かれることはないので、1つのファイル転送が倍速になるわけではない。

束ね方（モード）

方式モード特徴
手動onネゴシエーションしない。相手も on でないと束ならない
PAgP（Cisco 独自）desirable（誘う）／auto（誘われたら）
LACP（IEEE 802.3ad）active（誘う）／passive（誘われたら）標準なので他社の機器とも組める。最大 16 本（8本が稼働、8本が待機）

両端のモードを選ぶと、束なるかどうかと理由が出る。下の表のマスを押しても選べる。

束ねるために一致が必要なもの

メンバーのポートで、次の設定がすべて同じでないと束ならない。

  • 速度とデュプレックス
  • アクセスポートならアクセス VLAN、トランクならネイティブ VLAN と許可 VLAN
  • L2 か L3 か（switchport か no switchport）

1つでも違うと、そのポートは suspended（s） になって束から外れる。設定を直すときは、メンバーのポートではなく Port-channel 側を直すと、全メンバーにまとめて反映される。

設定例

interface range GigabitEthernet1/0/1 - 2   ! 束ねるポートをまとめて選ぶ
 channel-group 1 mode active   ! LACP で束ねる。Port-channel1 が自動で作られる
!
interface Port-channel1   ! 以後の設定はこちらに入れる（メンバーに反映される）
 switchport mode trunk   ! L2 のトランクとして束ねる
 switchport trunk allowed vlan 10,20,99   ! 運ぶ VLAN を決める

interface range GigabitEthernet1/0/3 - 4   ! 束ねるポートをまとめて選ぶ
 no switchport   ! 先に L3 のポートにする（L2 と L3 は混ぜられない）
 channel-group 2 mode active   ! LACP で束ねる。Port-channel2 が作られる
!
interface Port-channel2
 no switchport   ! Port-channel も L3 にする
 ip address 10.0.0.1 255.255.255.252   ! IP アドレスは Port-channel 側に付ける
L2 の EtherChannelL3 の EtherChannel
設定switchport のコマンドを使うno switchport にして、IP アドレスを付ける
役割スイッチのポートと同じ。VLAN のフレームを運ぶルータのインタフェースと同じ。ルーティングする
show の表示Po1(SU)：S ＝ Layer2Po2(RU)：R ＝ Layer3
よく使う場所スイッチ同士をつないで、VLAN を延ばすL3 スイッチ同士やルータとの間を経路で分ける（STP が要らない）

振り分け方は port-channel load-balance src-dst-ip などで変える（送信元・宛先 IP の組でハッシュ）。

show で確かめる

  • show etherchannel load-balance：振り分け方

束ならないときの切り分け

メンバーが (I) stand-alone になる
見る
show lacp neighbor（相手が LACP を話しているか）
原因
相手とネゴシエーションできていない。passive ＋ passive、auto ＋ auto、LACP と PAgP の混在、相手が束ねる設定をしていない
直し方
少なくとも片方を active（PAgP なら desirable）にし、両端のプロトコルをそろえる
メンバーが (s) suspended になる
見る
show interfaces Gi1/0/2 switchport、show running-config interface Gi1/0/2
原因
メンバー間で設定が違う（速度・デュプレックス、アクセス VLAN、ネイティブ VLAN、許可 VLAN、L2 と L3）
直し方
メンバーの設定をそろえる。以後の設定は Port-channel 側に入れる
どのメンバーも束に入らず、ポートが止まっている
見る

原因
片方だけ on にしたため、ループを防ぐしくみが働いて err-disabled になった。またはリンクが落ちている
直し方
両端のモードをそろえ、shutdown → no shutdown で戻す

3. STP

何のための技術か

L2 のループは、ブロードキャストが回り続けて増え、ネットワーク全体を止める。STP は、ループになるリンクの1か所をブロックして木の形にする。

Cisco の STP の種類

種類標準特徴
PVST+CiscoVLAN ごとに STP の木を作る。昔の Cisco の既定
Rapid PVST+CiscoVLAN ごとの RSTP。切替えが速い。よく使われる
RSTPIEEE 802.1w速い STP。木は1つ
MSTIEEE 802.1s複数の VLAN をまとめたインスタンスごとに木を作る。VLAN が多くても木の数が少なくて済む

ブリッジ ID

ブリッジ ID ＝ 優先度 ＋ 拡張システム ID（VLAN 番号） ＋ MAC アドレス。小さいほうが勝つ。優先度の既定は 32768 で、4096 の倍数でしか設定できない。優先度と VLAN を変えて、show に出る値を確かめる。

ルートブリッジとポートの決まり方

3台を三角形につないだ例（どのリンクも 1Gbps でコスト 4、SW1 のブリッジ ID が最小、SW2 が2番目）。

決めるもの比べる順番
ルートブリッジブリッジ ID が最小
ルートポート（各スイッチに1つ）① ルートまでのコストの合計が最小 → ② 相手のブリッジ ID が最小 → ③ 相手のポート ID が最小
指定ポート（各リンクに1つ）そのリンクで、ルートまでのコストが最小のスイッチのポート（同じならブリッジ ID が小さいほう）
残り代替ポート（Alternate）・バックアップポートとしてブロック

図では、SW2 と SW3 の間のリンクで、ルートまでのコストはどちらも 4。ブリッジ ID が小さい SW2 の側が指定ポートになり、SW3 の側がブロックされる。

帯域コスト（短い形式）
10Mbps100
100Mbps19
1Gbps4
10Gbps2

RSTP のポートの状態は Discarding・Learning・Forwarding の3つ。ポイントツーポイントのリンクでは、隣のスイッチと提案と合意（proposal／agreement）をやり取りして、タイマーを待たずにすぐ転送を始める。

設定例

spanning-tree mode rapid-pvst   ! Rapid PVST+ にする
spanning-tree vlan 10 root primary   ! VLAN 10 のルートになる（優先度 24576）
spanning-tree vlan 20 root secondary   ! VLAN 20 の予備のルート（優先度 28672）

spanning-tree mode rapid-pvst
spanning-tree vlan 20 root primary   ! VLAN 20 は SW2 をルートにする
spanning-tree vlan 10 root secondary
  • root primary は優先度を 24576（いまのルートがそれ以下なら、さらに 4096 小さい値）にする。直接 spanning-tree vlan 10 priority 4096 と書いてもよい
  • VLAN ごとにルートを分けると、VLAN ごとにブロックされるリンクが変わり、両方のリンクを使える（負荷分散）
  • ポート単位の調整は、インタフェースで spanning-tree vlan 10 cost 10 や spanning-tree vlan 10 port-priority 64
spanning-tree mode mst   ! MST にする
spanning-tree mst configuration   ! リージョンの設定に入る
 name REGION1   ! リージョン名
 revision 1   ! リビジョン番号
 instance 1 vlan 10,20   ! VLAN 10・20 をインスタンス 1 に
 instance 2 vlan 30,40   ! VLAN 30・40 をインスタンス 2 に
!
spanning-tree mst 1 root primary   ! インスタンス 1 のルートになる

名前・リビジョン番号・VLAN とインスタンスの対応がすべて同じスイッチが、同じ MST リージョンになる。1つでも違うと別のリージョンになり、意図どおりに動かない。どのインスタンスにも入れていない VLAN は、インスタンス 0（IST）に入る。

4. STP の保護機能

機能設定動き置く場所
PortFastspanning-tree portfastすぐ転送を始める（エッジポート）PC・サーバ用のポート
BPDU ガードspanning-tree bpduguard enableBPDU を受け取ったらポートを止める（err-disabled）PortFast のポート
BPDU フィルタspanning-tree bpdufilter enableBPDU を送受信しない使いどころは限られる（ループを見逃す危険）
ルートガードspanning-tree guard rootより強い BPDU を受けたらブロック（root-inconsistent）。届かなくなれば自動で戻るルートになってほしくない機器へ向かう下向きのポート
ループガードspanning-tree guard loopルートポート・代替ポートで BPDU が届かなくなっても、転送に切り替えない上向きのポート（片方向だけ通じるリンクの対策）
 
spanning-tree portfast default   ! アクセスポートすべてを PortFast に
spanning-tree portfast bpduguard default   ! PortFast のポートすべてに BPDU ガード
errdisable recovery cause bpduguard   ! err-disabled から自動で戻す（任意）

err-disabled になったポートは show interfaces status err-disabled で探し、原因を取り除いてから shutdown → no shutdown で戻す。

確認問題

カードを押すと、裏返って答えが出る。

両端のポートを dynamic auto にした。トランクになるか
ならない（アクセスポートになる）。auto はどちらも自分からは誘わないから。片方を desirable か trunk にする。
トランクに VLAN 30 を足そうとして switchport trunk allowed vlan 30 と打った。何が起きるか
許可 VLAN が 30 だけに置き換わる。足すときは allowed vlan add 30。
ネイティブ VLAN を、使わない VLAN（99 など）に変える理由
VLAN 1 には最初から端末が入っており、二重タグの攻撃に悪用されうるから。どのアクセスポートにも割り当てない VLAN にすれば、攻撃者がネイティブ VLAN に入れない。
show etherchannel summary で、メンバーに (s) が付いている。何を疑うか
suspended。メンバー間で速度・デュプレックス・VLAN の設定が一致しているか。
LACP で、両端を passive にした。束なるか
束ならない。どちらも自分からネゴシエーションを始めないから。片方を active にする。
L3 の EtherChannel で、IP アドレスを付けるのはどこか
Port-channel 側。メンバーは no switchport にして channel-group に入れるだけ。
VLAN 10 で、優先度を設定していないスイッチの show spanning-tree に出る優先度は
32778。既定の 32768 に、拡張システム ID の 10 が足される。
PC 用のポートに BPDU ガードを設定する理由
利用者がスイッチを勝手につなぐと、ループや STP の再計算が起きるおそれがある。BPDU を受けた時点でポートを止めて防ぐ。
MST で、2台を同じリージョンにするために一致させるものは
リージョン名・リビジョン番号・VLAN とインスタンスの対応の3つ。
