2. OSPF

何のための技術か

各ルータが自分のリンクの情報（LSA）をエリアの中に配り、全員が同じ地図（LSDB）を持つ。各ルータはその地図から、自分を根にした最短経路（SPF、ダイクストラ法）を計算する。地図を持っているので収束が速く、エリアに分けると大きなネットワークでも計算と LSA の量を抑えられる。メトリックはコスト（帯域幅から決まる）。

隣接ができるまで

  • DR でも BDR でもないルータ（DROTHER）同士は 2-Way で止まるのが正常。地図は DR・BDR とだけそろえる
  • ExStart・Exchange で止まるときは、まず MTU の不一致を疑う

隣接の条件

一致が必要一致しなくてよい
エリア IDプロセス ID（router ospf 1 の 1。ルータの中だけの番号）
hello・dead の秒数優先度（DR 選出に使うだけ）
サブネット（アドレスとマスク）コスト
認証の方式とキー
エリアの種類（スタブかどうか）
MTU（違うと ExStart・Exchange で止まる）
ルータ ID は重ならないこと

どちらかのインタフェースが passive-interface だと hello を送らないので、隣接はできない。

ルータ ID の決まり方

  1. router-id コマンドで決めた値
  2. なければ、ループバックのいちばん大きい IP アドレス
  3. それもなければ、動いている物理インタフェースのいちばん大きい IP アドレス

ルータ ID はプロセスが動き出したときに決まる。あとから router-id を変えても、隣接があるとすぐには変わらず、clear ip ospf process でプロセスをやり直す必要がある。

ネットワークタイプと DR・BDR

ネットワークタイプ既定になるところDR・BDRhello／dead
broadcastEthernet選ぶ10 秒／40 秒
point-to-pointシリアル（HDLC・PPP）、トンネル選ばない10 秒／40 秒

1つの LAN に何台もルータがいると、全員が全員と地図をそろえるのは無駄が多い。そこで代表の DR（と予備の BDR）を選び、ほかのルータ（DROTHER）は DR・BDR とだけ地図をそろえる。

  • 優先度（既定 1、0〜255）が大きい方が DR。同じならルータ ID が大きい方。優先度 0 は DR にも BDR にもならない
  • あとから優先度を上げても DR は交代しない（横取りしない）。DR を変えたいときは、DR・BDR のプロセスをやり直す
  • DROTHER は DR・BDR 宛てに 224.0.0.6 で送り、DR は全 OSPF ルータ宛ての 224.0.0.5 で配る
  • 2台だけの Ethernet のリンクは、ip ospf network point-to-point にすると DR 選出を省ける（Full になるのが速い）。両端でそろえること

LSA とエリア

LSA出すルータ中身届く範囲経路の表示
Type 1（Router）すべてのルータ自分のリンクとコストエリアの中O
Type 2（Network）DRその LAN にいるルータの一覧エリアの中O
Type 3（Summary）ABRほかのエリアの経路ほかのエリアへO IA
Type 4（ASBR Summary）ABRASBR がどこにいるかほかのエリアへ−
Type 5（External）ASBROSPF の外から入れた経路スタブ以外の全エリアO E2（O E1）
Type 7（NSSA External）NSSA の中の ASBR外部の経路（ABR で Type 5 に変える）NSSA の中O N2（O N1）
  • すべてのエリアはエリア 0 に接する。エリアとエリア 0 の境にいるのが ABR、外部の経路を入れるのが ASBR
  • E2（既定）はメトリックが外部で決めた値のまま。E1 は途中の OSPF のコストも足す
  • エリアの種類：スタブは Type 5 を入れず、代わりにデフォルトルート。トータリースタブ（Cisco）は Type 3 も入れない。NSSA はスタブだがエリアの中に ASBR を置ける（Type 7）

コスト

コスト ＝ 基準の帯域幅 ÷ インタフェースの帯域幅（小数は切り捨て、最小 1）。基準の既定は 100 Mbps なので、それより速いリンクはどれもコスト 1 になって区別できない。

インタフェース既定（基準 100 Mbps）基準を 100 Gbps にしたとき
FastEthernet（100 Mbps）11000
GigabitEthernet（1 Gbps）1100
TenGigabitEthernet（10 Gbps）110

基準は auto-cost reference-bandwidth 100000（単位は Mbps）で変える。全ルータでそろえること。1本だけ変えたいときは、インタフェースで ip ospf cost を直接決める。

設定例

router ospf 1   ! プロセス ID（ルータの中だけの番号。相手と合わせなくてよい）
 router-id 1.1.1.1   ! ルータ ID を決める
 auto-cost reference-bandwidth 100000   ! コストの基準を 100 Gbps に（全ルータでそろえる）
 passive-interface GigabitEthernet0/1   ! LAN 側は hello を送らない（経路は広告する）
 network 10.0.12.0 0.0.0.3 area 0   ! ワイルドカードマスクで一致したインタフェースを有効に
 network 192.168.1.0 0.0.0.255 area 0
 network 1.1.1.1 0.0.0.0 area 0   ! 0.0.0.0 は「この IP ちょうど」
  • network はインタフェースの IP アドレスと照らし合わせるだけ。広告する経路の長さは、インタフェースのマスクで決まる
  • LAN 側を passive にするのは、PC に hello を送らないため（勝手なルータとの隣接も防ぐ）。passive-interface default で全部を passive にして、no passive-interface で必要なところだけ戻す書き方もある
interface GigabitEthernet0/0
 ip ospf 1 area 0   ! このインタフェースをエリア 0 に（network より優先）
 ip ospf network point-to-point   ! 2台だけのリンクは DR を選ばない（両端でそろえる）
 ip ospf cost 10   ! コストを直接決める
!
interface Loopback0
 ip ospf 1 area 0

どのインタフェースがどのエリアか、設定を見ただけで分かるのが利点。show ip ospf interface では「Attached via Interface Enable」と出る。

router ospf 1
 area 1 range 10.1.0.0 255.255.0.0   ! ABR で、エリア 1 の経路を1本にまとめてほかのエリアへ
 summary-address 172.16.0.0 255.255.0.0   ! ASBR で、外部から入れた経路をまとめる
 area 1 filter-list prefix BLOCK-10 in   ! ABR で、エリア 1 に入る Type 3 を止める
 distribute-list prefix BLOCK-10 in   ! このルータのルーティングテーブルに入れない
!
ip prefix-list BLOCK-10 seq 5 deny 10.9.9.0/24   ! 10.9.9.0/24 だけ止める
ip prefix-list BLOCK-10 seq 10 permit 0.0.0.0/0 le 32   ! ほかはすべて通す

エリアの中では全員の地図が同じでなければならないので、LSA そのものは止められない。distribute-list … in は自分のルーティングテーブルに入れないだけで、LSA はほかのルータに伝わり続ける。エリアの外へ出さないようにしたいときは、ABR で集約するか、filter-list で Type 3 を止める。

OSPFv3（IPv6）

しくみは v2 と同じ（エリア、DR・BDR、SPF）。違うのは次のところ。

  • インタフェースで有効にする（network コマンドはない）
  • 隣とはリンクローカルアドレスでやり取りする
  • ルータ ID は 32 ビットのまま。IPv4 アドレスが1つもなければ router-id が必須
  • アドレスの情報は新しい LSA（Type 8 Link、Type 9 Intra-Area Prefix）で運ぶ
ipv6 unicast-routing   ! IPv6 のルーティングを有効に
!
router ospfv3 1
 router-id 1.1.1.1   ! IPv4 アドレスがなければ必須
!
interface GigabitEthernet0/0
 ipv6 address 2001:DB8:12::1/64
 ospfv3 1 ipv6 area 0   ! インタフェースで有効にする

確かめるときは show ospfv3 neighbor、show ipv6 route ospf。

DUAL：予備の経路を先に用意しておく

用語意味上の図では
RD（Reported Distance）隣から宛先までの距離（隣が知らせてきた値）R2 経由 10、R3 経由 15、R4 経由 25
FD（Feasible Distance）自分から宛先までの距離（RD ＋ 隣までの距離）20・30・35
サクセサFD がいちばん小さい、いま使う経路R2 経由（FD 20）
フィージブルサクセサ（FS）ループしないと分かっている予備の経路。条件は RD ＜ サクセサの FDR3 経由（RD 15 ＜ 20）。R4 経由は RD 25 なので FS にならない
  • サクセサが切れても FS があれば、計算し直さずにすぐ切り替わる（これが収束の速さの理由）
  • FS がないと、その経路は Active になり、隣に問い合わせ（Query）を出して探し直す
  • variance 2 にすると、FD がサクセサの 2 倍未満で、FS の条件を満たす経路も使う（不等コストの負荷分散）。上の図なら R3 経由（30 ＜ 40）も使う
  • メトリックは既定で、経路の中でいちばん小さい帯域幅と、遅延の合計から計算する
router eigrp 100   ! AS 番号（隣と合わせる）
 network 10.0.0.0 0.0.255.255   ! 有効にするインタフェース
 passive-interface GigabitEthernet0/1
 variance 2   ! 不等コストの負荷分散

router eigrp CORP   ! 名前は自由
 address-family ipv4 unicast autonomous-system 100   ! AS 番号はここで決める
  network 10.0.0.0 0.0.255.255
  af-interface GigabitEthernet0/1
   passive-interface   ! インタフェースごとの設定はここにまとまる
  exit-af-interface
  topology base
   variance 2

確かめるときは show ip eigrp neighbors、show ip eigrp topology（サクセサと FS が見える）。

4. BGP（eBGP）

何のための技術か

AS（組織ごとのネットワーク）の間で経路をやり取りするプロトコル。経路に通ってきた AS の一覧（AS_PATH）を付けて伝える（パスベクタ）。自分の AS 番号が入った経路は受け取らないので、ループしない。速さよりも、どの経路を使うかを細かく決められる（ポリシー）ことが大事。

eBGPiBGP
相手違う AS同じ AS
AD20200
AS_PATH送るときに自分の AS を足す足さない（だから iBGP で受けた経路は、ほかの iBGP の相手に渡さない）
ネクストホップ自分に書き換える書き換えない
相手との距離既定では直接つながった相手だけ（TTL 1）どこでもよい（ループバック同士が多い）

ネイバーができるまで

BGP は TCP 179 番で相手とつなぐ。相手は自動では見つからないので、neighbor で1台ずつ書く。

つながる条件は次の3つ。

  • remote-as が相手の本当の AS 番号と一致する（違うと %BGP-3-NOTIFICATION … peer in wrong AS）
  • 相手の IP アドレスに届く
  • 相手の設定の neighbor が、こちらが送る IP アドレスになっている。ループバック同士でつなぐときは update-source が要り、eBGP なら ebgp-multihop も要る

設定例

router bgp 65001   ! 自分の AS 番号
 bgp router-id 1.1.1.1   ! ルータ ID（決め方は OSPF と同じ）
 neighbor 203.0.113.2 remote-as 65002   ! 相手の IP と、相手の AS 番号
 network 172.16.10.0 mask 255.255.255.0   ! ルーティングテーブルと同じ長さで書く

network は、ルーティングテーブルに同じアドレス・同じ長さの経路があるときだけ広告する。mask を省くとクラスフルの長さ（172.16.10.0 なら /16）として扱われるので、/24 の経路しかなければ広告されない。

同じ宛先に複数の経路があるとき、上から順に比べて、差がついたところで決める。

ポリシー（route-map）

ip prefix-list DEFAULT seq 5 permit 0.0.0.0/0   ! デフォルトルートだけに一致
!
route-map FROM-ISP1 permit 10
 match ip address prefix-list DEFAULT
 set local-preference 200   ! ISP1 から来たデフォルトルートを優先（出ていく道）
route-map FROM-ISP1 permit 20   ! ほかの経路はそのまま受け取る
!
route-map TO-ISP2 permit 10
 set as-path prepend 65001 65001   ! AS_PATH を長く見せて、ISP2 からは入りにくくする
!
router bgp 65001
 neighbor 203.0.113.2 route-map FROM-ISP1 in
 neighbor 198.51.100.2 route-map TO-ISP2 out
  • route-map は、どの行にも一致しなかった経路を捨てる（最後に見えない deny がある）。ほかを通すなら、条件なしの permit を最後に置く
  • ポリシーを変えたら、clear ip bgp * soft で経路を流し直す（接続は切らない）

OSPF が 10.1.1.0/24、EIGRP が 10.1.0.0/16 を知っている。10.1.1.5 宛てはどちらを使うか
OSPF（/24）。最長一致が先に効く。AD を比べるのは長さが同じときだけ。
OSPF の隣接で、一致しなくてよいものを2つ
プロセス ID、優先度（コストも）。エリア・hello と dead・サブネット・認証・エリアの種類・MTU は一致が必要。
隣接が ExStart のまま進まない。まず何を疑うか
MTU の不一致。
show ip ospf neighbor で 2WAY/DROTHER と出た。異常か
正常。DROTHER 同士は 2-Way で止まり、地図は DR・BDR とだけそろえる。
優先度がすべて 1 の LAN で、DR になるのはどのルータか
ルータ ID がいちばん大きいルータ。ただし、後から来たルータは DR を横取りしない。
ルーティングテーブルの O IA と O E2 は、それぞれどの LSA から来た経路か
O IA は ABR の Type 3（ほかのエリア）、O E2 は ASBR の Type 5（OSPF の外）。
GigabitEthernet と 10 Gigabit のコストが同じになる。なぜか、どう直すか
基準の帯域幅の既定が 100 Mbps で、どちらも 1 になるから。auto-cost reference-bandwidth を全ルータで大きくする。
distribute-list … in で経路を止めた。ほかのルータにも伝わらなくなるか
伝わる。自分のルーティングテーブルに入れないだけで、LSA は止まらない。エリアの外へ出さないなら ABR で集約か filter-list。
EIGRP のフィージブルサクセサの条件は
その経路の RD（隣から宛先までの距離）が、サクセサの FD より小さいこと。ループしないことが保証される。
OSPF にはできず、EIGRP にはできる負荷分散は
不等コストの負荷分散（variance）。OSPF は等コストだけ。
BGP の network 172.16.10.0 と書いたのに広告されない。テーブルには 172.16.10.0/24 がある
mask を省いたので /16 として扱われ、テーブルに同じ経路がないから。network 172.16.10.0 mask 255.255.255.0 と書く。
show ip bgp summary の State が Active。どういう状態か
つながっていない（接続を試し直している）。届くか、remote-as が合っているかを確かめる。
自分の AS から出ていく道を、AS の中のすべてのルータで同じように選ばせたい。どの属性を使うか
Local Preference（大きい方が優先、AS の中に伝わる）。Weight はそのルータの中だけ。
よその AS から入ってくる道を、こちらの回線にしてほしくない。何をするか
その回線から出す経路に AS_PATH のプリペンド（自分の AS を重ねて遠回りに見せる）。MED を使うこともある。
