5束ならないときの切り分け

症状を開くと、見るコマンドと原因、直し方が出る。

メンバーが (I) stand-alone になる
見る
show lacp neighbor（相手が LACP を話しているか）
原因
相手とネゴシエーションできていない。passive ＋ passive、auto ＋ auto、LACP と PAgP の混在、相手が束ねる設定をしていない
直し方
少なくとも片方を active（PAgP なら desirable）にし、両端のプロトコルをそろえる
メンバーが (s) suspended になる
見る
show interfaces Gi1/0/2 switchport、show running-config interface
原因
メンバー間で設定が違う（速度・デュプレックス、アクセス VLAN、ネイティブ VLAN、許可 VLAN、L2 と L3）
直し方
メンバーの設定をそろえる。以後の設定は Port-channel 側に入れる
Port-channel が (SD) で、どのメンバーも束に入らない
見る
show interfaces status、show interfaces status err-disabled
原因
メンバーのリンクが落ちている、または片方だけ on にしてループ防止で err-disabled になっている
直し方
配線と両端のモードを確かめ、shutdown → no shutdown で戻す

6確認問題

カードを押すと、裏返って答えが出る。

LACP で両端を passive にした。束なるか押して答えを見る
束ならない。passive はどちらも自分からネゴシエーションを始めない。片方を active にする。
2本を束ねたのに、1つのファイル転送の速度が変わらない理由押して答えを見る
振り分けがフローごとなので、1つの通信は1本のリンクしか使わないから。
L3 の EtherChannel で、IP アドレスを付けるのはどこか押して答えを見る
Port-channel 側。メンバーのポートには付けない（メンバーは no switchport にして channel-group に入れる）。
