1. FHRP（ゲートウェイの冗長化）

何のための技術か

PC はデフォルトゲートウェイを1つしか設定できない。そのルータが止まると、LAN の外へ出られなくなる。FHRP（First Hop Redundancy Protocol）は、複数のルータで1つの仮想 IP アドレスと仮想 MAC アドレスを共有し、そのうちの1台が実際に転送する。止まったら、別のルータが同じ仮想アドレスを引き継ぐので、PC の設定は変えなくてよい。

HSRP・VRRP・GLBP の違い

HSRPVRRPGLBP
規格Cisco 独自標準（RFC 5798）Cisco 独自
役割の名前Active・StandbyMaster・BackupAVG（まとめ役）・AVF（転送役）
転送するルータActive の1台Master の1台複数で分担（負荷分散）
優先度の既定100100（仮想 IP が自分のアドレスなら 255）100
preempt の既定無効有効無効（AVG）
仮想 IP実アドレスとは別実アドレスと同じにもできる実アドレスとは別
仮想 MACv1：0000.0c07.acXX
v2：0000.0c9f.fXXX		0000.5e00.01XXAVF ごとに別の MAC
宛先v1：224.0.0.2
v2：224.0.0.102		224.0.0.18224.0.0.102
タイマーhello 3 秒・hold 10 秒広告 1 秒hello 3 秒・hold 10 秒

XX はグループ番号（16 進数）。HSRP v1 のグループは 0〜255、v2 は 0〜4095 で、IPv6 にも使える。v1 と v2 は通じないので、両方のルータでそろえる。

Active の決まり方と preempt

  • 優先度が大きい方が Active。同じなら、インタフェースの IP アドレスが大きい方
  • HSRP は preempt が既定で無効。あとから優先度の高いルータが来ても、いまの Active から役割を奪わない。奪わせたいときは standby 1 preempt
  • HSRP の状態は Initial → Learn → Listen → Speak → Standby → Active の順に進む。Speak で hello を出し合って役割を決める

トラッキング：上流が切れたら役割を譲る

Active のルータの上流（WAN 側）が切れても、LAN 側が生きていれば Active のままになり、PC の通信は行き止まりになる。トラッキングで上流を見張り、切れたら優先度を下げて、Standby に役割を譲る。

track 1 interface GigabitEthernet0/0 line-protocol   ! 上流のインタフェースを見張る
!
interface GigabitEthernet0/1
 standby 1 track 1 decrement 20   ! 切れたら優先度を 110 → 90 に下げる

譲るには、相手（R2）にも preempt が必要。R1 の優先度が 90 に下がっても、R2 に preempt がなければ R2 は Active にならない。

設定例

interface GigabitEthernet0/1
 ip address 192.168.1.2 255.255.255.0
 standby version 2   ! v2 にする（両方のルータでそろえる）
 standby 1 ip 192.168.1.1   ! グループ 1 の仮想 IP（PC のゲートウェイ）
 standby 1 priority 110   ! 既定の 100 より大きくして Active にする
 standby 1 preempt   ! 優先度が高ければ Active を奪う

interface GigabitEthernet0/1
 ip address 192.168.1.3 255.255.255.0
 standby version 2
 standby 1 ip 192.168.1.1   ! 同じグループ・同じ仮想 IP
 standby 1 preempt   ! 優先度は既定の 100 のまま

interface GigabitEthernet0/1
 ip address 192.168.1.2 255.255.255.0
 vrrp 1 ip 192.168.1.1   ! グループ 1 の仮想 IP
 vrrp 1 priority 110   ! preempt は既定で有効

fhrp version vrrp v3   ! VRRPv3 の書き方を使う
!
interface GigabitEthernet0/1
 vrrp 1 address-family ipv4   ! IPv4 のグループ 1
  address 192.168.1.1 primary   ! 仮想 IP
  priority 110

2. NAT・PAT

何のための技術か

社内ではプライベートアドレス（192.168.0.0/16 など）を使い、インターネットに出るときだけグローバルアドレスに変換する。グローバルアドレスが少なくても多くの端末が外に出られ、社内のアドレスを外に見せずに済む。

4つのアドレスの呼び方

呼び方意味上の図では
Inside local内側の端末の本当のアドレス192.168.1.10
Inside global内側の端末が外から見えるアドレス（変換後）203.0.113.1
Outside local外側の相手が、内側から見えるアドレス198.51.100.10（ふつうは変換しない）
Outside global外側の相手の本当のアドレス198.51.100.10

local は「内側から見たアドレス」、global は「外側から見たアドレス」と覚える。

NAT の種類

種類変換のしかた使いどころ
静的 NAT1 対 1 で固定外から接続されるサーバ（外からの通信も通る）
動的 NATプールのアドレスを、通信のたびに 1 対 1 で貸し出すプールが足りなくなると、それ以上の端末は外に出られない
PAT（overload）1つのアドレスを、ポート番号で多くの端末が共有家庭や会社でいちばん使われる形

設定例

どの形でも、まず内側と外側のインタフェースを決める。

interface GigabitEthernet0/0
 ip nat inside   ! LAN 側が内側
interface GigabitEthernet0/1
 ip nat outside   ! ISP 側が外側

access-list 1 permit 192.168.1.0 0.0.0.255   ! 変換する相手（社内の LAN）
ip nat inside source list 1 interface GigabitEthernet0/1 overload   ! Gi0/1 のアドレスを共有

ip nat pool PUBLIC 203.0.113.2 203.0.113.5 netmask 255.255.255.248   ! 貸し出すアドレスの範囲
access-list 1 permit 192.168.1.0 0.0.0.255
ip nat inside source list 1 pool PUBLIC   ! overload を付けると、プールで PAT になる

ip nat inside source static 192.168.1.20 203.0.113.2   ! サーバを 1 対 1 で固定
ip nat inside source static tcp 192.168.1.21 80 203.0.113.3 80   ! ポートだけを固定することもできる

3. NTP と PTP

何のための技術か

機器の時刻がずれていると、ログの時刻が合わず障害の調査ができない。証明書の有効期限の判定や、認証（AAA）にも影響する。NTP はネットワーク越しに時刻を合わせるプロトコル（UDP 123 番）。

stratum：基準の時計から何段目か

  • NTP サーバが複数あると、stratum が小さく信頼できる方を基準（sys.peer）に選ぶ
  • 本物の機器では、設定してから同期するまでに数分かかる

設定例

ntp server 10.0.0.123   ! このサーバに時刻を合わせる（クライアント）
ntp server 10.0.0.124   ! 予備のサーバ
ntp source Loopback0   ! NTP の送信元をループバックにする
!
ntp authenticate   ! 認証を使う
ntp authentication-key 1 md5 CISCO123   ! 鍵を決める
ntp trusted-key 1   ! この鍵を信頼する
ntp server 10.0.0.123 key 1   ! サーバとのやり取りに鍵を使う
コマンド役割
ntp server相手に合わせる（クライアント）
ntp peer同じ立場の相手と、互いに合わせる
ntp master 3自分の時計を基準として配る（外の基準がないとき）。数字は自分の stratum

show で確かめる

  address         ref clock       st   when   poll reach  delay  offset   disp
*~10.0.0.123      .GPS.            1     12     64   377  1.012   0.214  0.950
+~10.0.0.124      10.0.0.123       2     12     64   377  1.012   0.214  0.950
 * sys.peer, # selected, + candidate, - outlyer, x falseticker, ~ configured

R1# show ntp status
Clock is synchronized, stratum 2, reference is 10.0.0.123

PTP（IEEE 1588）

NTP の精度はミリ秒程度。PTP は、機器のハードウェアで送受信の時刻を記録して、マイクロ秒より細かい精度で合わせる。工場の制御、放送、金融の取引など、より正確な時刻が要る場面で使う。

NTPPTP
精度ミリ秒程度マイクロ秒より細かい
時刻の記録ソフトウェアハードウェア（タイムスタンプ）
基準の選び方stratum などBMCA で、いちばんよい時計（グランドマスター）を自動で選ぶ
途中の機器特になしバウンダリクロック（受けて合わせ直す）、トランスペアレントクロック（通過にかかった時間を書き足す）

4. マルチキャスト

何のための技術か

同じデータ（映像の配信など）を多くの受信者に届けるとき、ユニキャストでは受信者の数だけ送ることになる。マルチキャストでは、送信者は1つのグループアドレス宛てに1回だけ送り、ルータが受信者のいる方向にだけ複製して届ける。

アドレス用途
224.0.0.0/4マルチキャスト全体（224.0.0.0〜239.255.255.255）
224.0.0.0/24同じリンクの中だけ（ルータを越えない）。OSPF の 224.0.0.5 など
232.0.0.0/8SSM 用
239.0.0.0/8組織の中で自由に使える範囲

MAC アドレスは 01:00:5E に、グループアドレスの下位 23 ビットを付けたもの。

プロトコルの役割

プロトコルどこで使うか役割
IGMP受信者とルータの間受信者が「このグループを受けたい」とルータに伝える。v2 はグループだけを指定、v3 は送信元も指定できる（SSM に必要）
IGMP スヌーピングスイッチIGMP を覗き見て、受信者のいるポートにだけ流す
PIMルータ同士マルチキャストを届ける道（配信の木）を作る
MSDPRP 同士別の PIM のドメインの RP どうしで、「どこに送信者がいるか」を伝え合う

PIM の種類

種類しくみ向いている場面
PIM-SM（スパースモード）受信者がいる方向から RP（待ち合わせ場所のルータ）へ参加を伝え、まず RP を通る共有の木（*,G）で届ける。流れ始めたら、送信者への最短の木（S,G）に切り替えるいちばん使われる
PIM-DM（デンスモード）まず全体に流し、受信者がいない方向から止めてもらう（flood and prune）受信者がどこにでもいる小さな環境
SSM受信者が IGMPv3 で送信者を指定するので、RP が要らない。最初から（S,G）の木送信者が決まっている配信
Bidir-PIM共有の木を双方向に使い、最短の木に切り替えない送信者も受信者も多い（多対多）

RPF チェック：ルータは、マルチキャストを受けたとき、送信者（または RP）へのユニキャストの経路が出ていくインタフェースから来たものだけを受け入れ、ほかから来たものは捨てる。これでループを防ぐ。マルチキャストが届かないときは、ユニキャストの経路も確かめる。

確認問題

カードを押すと答えが出る。

HSRP で R1 の優先度を 110 にしたのに、R2（100）が Active のまま。なぜか
HSRP は preempt が既定で無効だから。R1 に standby 1 preempt を入れる。
HSRP と VRRP で、preempt の既定はそれぞれどうか
HSRP は無効、VRRP は有効。
HSRP で優先度が同じとき、Active になるのはどちらか
インタフェースの IP アドレスが大きい方。
HSRP v1 のグループ 1 の仮想 MAC アドレスは
0000.0c07.ac01（v2 なら 0000.0c9f.f001）。
仮想 IP をルータ自身のインタフェースのアドレスと同じにできるのはどれか
VRRP。そのルータは優先度 255（アドレスの持ち主）になる。
トラッキングで R1 の優先度が下がったのに、R2 が Active にならない。何を疑うか
R2 に preempt がないこと。下げた後の優先度が R2 より小さいかも確かめる。
NAT の Inside local と Inside global の違いは
Inside local は内側の端末の本当のアドレス、Inside global は外から見えるアドレス（変換後）。
1つのグローバルアドレスを多くの端末で共有する NAT の設定で、必ず付けるキーワードは
overload（PAT）。
NAT を設定したのに show ip nat translations に何も出ない。まず何を確かめるか
インタフェースの ip nat inside と ip nat outside が逆になっていないか、アクセスリストが端末に一致しているか。
外から接続されるサーバに使う NAT の種類は
静的 NAT（1 対 1 で固定するので、外からの通信も通る）。
stratum 1 のサーバに合わせたルータの stratum は。stratum 16 は何を表すか
2（1段下）。stratum 16 は同期していない。
PTP が NTP より正確なのはなぜか
送受信の時刻をハードウェアで記録し、途中の機器でかかった時間も補正するから（マイクロ秒より細かい精度）。
SSM で RP が要らないのはなぜか。受信者に必要なものは
受信者が送信者を指定するので、待ち合わせ場所（RP）が要らない。受信者側には IGMPv3 が必要。
RPF チェックとは何か
マルチキャストを、送信者へのユニキャストの経路が出ていくインタフェースから来たときだけ受け入れるしくみ。ループを防ぐ。
