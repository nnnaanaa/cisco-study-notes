# 01-L2.md
## L2（トランク・EtherChannel・STP）

***

ENCOR の「インフラ」分野のうち、L2 で問われるのは次の3つ。

| テーマ | 出題のポイント |
| --- | --- |
| **トランク** | 802.1Q のトランクを、手動（静的）と **DTP**（自動）で組む。つながらないときの切り分け |
| **EtherChannel** | 手動（**on**）、**PAgP**、**LACP** で束ねる。束ならないときの切り分け |
| **STP** | **Rapid PVST+** と **MST** の設定と確認。**ルートガード**・**BPDU ガード**などの保護機能 |

どれも「**設定して、show で確かめ、おかしければ直す**」までできるようにする。

## 1. VLAN とトランク

### 何のための技術か

- **VLAN**：1台のスイッチの中を、**別々のブロードキャストドメインに分ける**
- **トランク**：1本のリンクで**複数の VLAN のフレームを運ぶ**。どの VLAN のフレームかは、**802.1Q のタグ**で見分ける

```mermaid
flowchart LR
  P1["PC"] -- "VLAN 10" --- S1["SW1"]
  S1 == "トランク<br>タグ付き" === S2["SW2"]
  S2 -- "VLAN 10" --- P2["PC"]
```

- PC とスイッチの間は**アクセスポート**（タグなし）、スイッチ同士は**トランク**（VLAN ごとにタグを付けて運ぶ）

### しくみ

| 項目 | 内容 |
| --- | --- |
| 802.1Q のタグ | フレームに **4Byte** を挿入する。中身は TPID（**0x8100**）、優先度 PCP（3bit）、DEI（1bit）、**VLAN ID（12bit）** |
| VLAN ID の範囲 | **1〜4094**（標準範囲 1〜1005、拡張範囲 1006〜4094） |
| **ネイティブ VLAN** | トランクで**タグを付けずに**送る VLAN。既定は **VLAN 1**。**両端で一致**させる |
| 許可 VLAN | トランクで運ぶ VLAN の一覧。既定は**すべて** |

### ネイティブ VLAN

トランクでは、ふつうはフレームに **VLAN のタグを付けて**運ぶ。ただし **1つの VLAN だけはタグを付けずに**送る。これがネイティブ VLAN。

| トランクで受け取ったフレーム | どの VLAN として扱うか |
| --- | --- |
| タグ付き（VLAN 20 など） | **タグに書いてある VLAN** |
| **タグなし** | **ネイティブ VLAN**（既定は VLAN 1） |

- タグを理解できない機器がトランクの途中にあっても通信できるようにするためのしくみ（今の構成ではほとんど使わない）

**両端で一致させる理由**：違っていると、**別の VLAN にフレームが漏れる**。

```mermaid
flowchart LR
  S1["SW1<br>ネイティブ 10"] -- "VLAN 10 を<br>タグなしで" --> S2["SW2<br>ネイティブ 20"]
  S2 -- "VLAN 20 へ" --> P["VLAN 20<br>の PC"]
```

1. SW1 は、VLAN 10 のフレームを「ネイティブだから」**タグなし**で送る
2. SW2 は、タグなしのフレームを「**自分のネイティブ VLAN 20**」として扱う
3. VLAN 10 の通信が、VLAN 20 に流れ込む → Cisco の機器は CDP で不一致を見つけ、`NATIVE_VLAN_MISMATCH` のログを出す

**ネイティブ VLAN を VLAN 1 のままにせず、使わない VLAN（例：99）に変える理由**

| 理由 | 内容 |
| --- | --- |
| VLAN 1 には、何もしなくても端末が入っている | **すべてのポートは最初から VLAN 1**。設定し忘れたポートや空いているポートにつないだ PC も、VLAN 1 に入る |
| **二重タグの攻撃**を防ぐ | 攻撃者がタグを2枚重ねたフレームを送ると、1台目のスイッチが外側のタグ（ネイティブ VLAN）を外し、2台目が内側のタグを読むので、**別の VLAN に入り込める**。攻撃者が**ネイティブ VLAN の中にいる**ことが条件なので、ネイティブ VLAN を**どのアクセスポートにも割り当てない VLAN** にすれば防げる |
| VLAN 1 は何にも使わないのが定番 | VLAN 1 は**削除できず**、CDP・DTP・VTP・PAgP などの制御用のフレームも VLAN 1 で送られる。利用者の通信を混ぜない |

- 99 という番号に意味はない。**どのアクセスポートにも割り当てていない VLAN** であればよい
- ネイティブ VLAN のフレームにもタグを付ける設定もある：`vlan dot1q tag native`（グローバル設定）
- 使わないポートは `shutdown` し、使わない VLAN（例：999）に入れておく
- 「VLAN 1」はネットワーク（ポートの集まり）で、**ループバック**（どのネットワークにも属さない、機器の中だけのインタフェース）とは関係ない。`interface Vlan1` は、VLAN 1 の中に置いたスイッチ自身のインタフェース（**SVI**）

### 設定例

```
vlan 10
 name SALES
vlan 20
 name DEV
!
interface GigabitEthernet1/0/1
 switchport mode access
 switchport access vlan 10
!
interface GigabitEthernet1/0/24
 switchport trunk encapsulation dot1q
 switchport mode trunk
 switchport trunk native vlan 99
 switchport trunk allowed vlan 10,20,99
 switchport nonegotiate
```

- `switchport trunk encapsulation dot1q` は、ISL にも対応した一部の機種でだけ必要（802.1Q しかない機種では打てない）
- `allowed vlan` を**あとから足す**ときは `switchport trunk allowed vlan add 30`。`add` を忘れると、**一覧が 30 だけに置き換わる**
- `nonegotiate` は **DTP を止める**（相手との自動ネゴシエーションをしない）

### DTP：トランクを自動で組むしくみ

**DTP** は Cisco 独自の、トランクにするかどうかを相手と自動で決めるプロトコル。

| モード | 動き |
| --- | --- |
| `access` | 常にアクセスポート |
| `trunk` | 常にトランク（DTP も送る） |
| `dynamic desirable` | **自分からトランクにしようと働きかける** |
| `dynamic auto` | **相手から誘われたらトランクになる**（自分からは誘わない） |

| 自分 ＼ 相手 | dynamic auto | dynamic desirable | trunk | access |
| --- | --- | --- | --- | --- |
| **dynamic auto** | **アクセス** | トランク | トランク | アクセス |
| **dynamic desirable** | トランク | トランク | トランク | アクセス |
| **trunk** | トランク | トランク | トランク | （不一致） |
| **access** | アクセス | アクセス | （不一致） | アクセス |

- **auto どうしはトランクにならない**（どちらも誘わないから）。よく問われる
- DTP を動かしたままにすると、攻撃者の PC が**スイッチのふりをしてトランクを組み、すべての VLAN に入れてしまう**（VLAN ホッピング）。そのため、ポートは `access` か `trunk` に固定し、トランクには `nonegotiate` を付けるのが基本

### show で確かめる

```
show interfaces trunk
```

```
Port        Mode         Encapsulation  Status        Native vlan
Gi1/0/24    on           802.1q         trunking      99

Port        Vlans allowed on trunk
Gi1/0/24    10,20,99

Port        Vlans allowed and active in management domain
Gi1/0/24    10,20,99

Port        Vlans in spanning tree forwarding state and not pruned
Gi1/0/24    10,20,99
```

| 見るところ | 分かること |
| --- | --- |
| Status | **trunking** ならトランクになっている |
| Native vlan | 相手と**同じ値か** |
| allowed on trunk | 許可した VLAN |
| allowed and active | そのうち、**このスイッチに VLAN が作られている**もの |
| forwarding state and not pruned | そのうち、**STP で転送中**のもの。ここにない VLAN は、この先へ流れない |

- `show interfaces Gi1/0/24 switchport`：**Administrative Mode**（設定したモード）と **Operational Mode**（実際の状態）を比べられる
- `show vlan brief`：VLAN と**アクセスポート**の一覧。**トランクのポートはここに出ない**

### よくあるトラブル

| 症状 | 原因 | 直し方 |
| --- | --- | --- |
| トランクにならない | 両端が `dynamic auto`、または片方が `access` | 両端を `trunk` にそろえる |
| 一部の VLAN だけ通らない | **許可 VLAN に入っていない**、またはその VLAN を**作っていない** | `allowed vlan add`、`vlan` で作る |
| ネイティブ VLAN 不一致のログが出る | 両端の `native vlan` が違う | 両端を同じ値にする（違うと、タグなしのフレームが**別の VLAN に漏れる**） |

## 2. EtherChannel

### 何のための技術か

複数の物理リンクを**1本の論理リンク（Port-channel）**に束ねる。

- 帯域が増え、1本が切れても通信が続く
- STP からは**1本のリンクに見える**ので、**ブロックされずに全部のリンクを使える**
- 振り分けは**フローごと**（ハッシュ）。**1つの通信は1本分の速度**しか出ない

### 束ね方（モード）

| 方式 | モード | 特徴 |
| --- | --- | --- |
| 手動 | `on` | ネゴシエーションしない。**相手も `on`** でないと束ならない |
| **PAgP**（Cisco 独自） | `desirable`（誘う）／`auto`（誘われたら） | |
| **LACP**（IEEE 802.3ad） | `active`（誘う）／`passive`（誘われたら） | 標準なので**他社の機器とも組める**。最大 16 本（8本が稼働、8本が待機） |

| 組合せ | 結果 |
| --- | --- |
| on ＋ on | 束なる |
| desirable ＋ desirable／auto | 束なる |
| **auto ＋ auto** | **束ならない** |
| active ＋ active／passive | 束なる |
| **passive ＋ passive** | **束ならない** |
| on ＋ PAgP や LACP、PAgP ＋ LACP | 束ならない |

> [!TIP]
> DTP と同じで、**「誘われ待ち」どうしは何も起きない**。auto ＋ auto、passive ＋ passive は束ならない。

### 束ねるために一致が必要なもの

メンバーのポートで、次の設定が**すべて同じ**でないと束ならない（一部のポートが外される）。

- **速度とデュプレックス**
- アクセスポートなら**アクセス VLAN**、トランクなら**ネイティブ VLAN と許可 VLAN**
- **L2 か L3 か**（`switchport` か `no switchport`）

> [!WARNING]
> 1つでも違うと、そのポートは **suspended（s）** になって束から外れる。設定を直すときは、メンバーのポートではなく **Port-channel 側**を直すと、全メンバーにまとめて反映される。

### 設定例

```config
interface range GigabitEthernet1/0/1 - 2   ! 束ねるポートをまとめて選ぶ
 channel-group 1 mode active   ! LACP で束ねる。Port-channel1 が自動で作られる
!
interface Port-channel1   ! 以後の設定はこちらに入れる
 switchport mode trunk   ! L2 のトランクとして束ねる
 switchport trunk allowed vlan 10,20,99
```

- 上の例は **L2 の EtherChannel**（`switchport` のコマンドでトランクとして束ねている）
- 振り分け方は `port-channel load-balance src-dst-ip` などで変える（送信元・宛先 IP の組でハッシュ）

### L2 と L3 の EtherChannel

| | L2 の EtherChannel | L3 の EtherChannel |
| --- | --- | --- |
| 設定 | **`switchport`** のコマンドを使う（`switchport mode trunk` など） | **`no switchport`** にして、**IP アドレス**を付ける |
| 役割 | スイッチのポートと同じ。VLAN のフレームを運ぶ（アクセスかトランク） | ルータのインタフェースと同じ。ルーティングする |
| `show etherchannel summary` | Po1(**S**U)：**S** ＝ Layer2 | Po2(**R**U)：**R** ＝ Layer3 |
| よく使う場所 | スイッチ同士をつないで、**VLAN を延ばす** | L3 スイッチ同士やルータとの間を、**経路で分ける**（STP が要らない） |

**L3 の EtherChannel の設定例**

```
interface range GigabitEthernet1/0/3 - 4
 no switchport
 channel-group 2 mode active
!
interface Port-channel2
 no switchport
 ip address 10.0.0.1 255.255.255.252
```

- メンバーのポートを**先に `no switchport`** にしてから `channel-group` を入れる。L2 のポートと L3 の Port-channel は混ぜられない
- IP アドレスは **Port-channel 側**に付ける（メンバーには付けない）
- 確認は `show etherchannel summary` で **Po2(RU)** になっているかを見る

### show で確かめる

両方のスイッチで設定したら、`show etherchannel summary` で束なったかを確かめる。

```config
interface range Gi1/0/1 - 2
 channel-group 1 mode active
```

```show
SW1# show etherchannel summary
Group  Port-channel  Protocol  Ports
------+-------------+---------+----------------------
1      Po1(SU)        LACP     Gi1/0/1(P) Gi1/0/2(P)
```

| 表示 | 意味 |
| --- | --- |
| Po1(**SU**) | **L2** で **使用中**。正常 |
| Gi1/0/1(**P**) | 束ねられている。正常 |
| (**s**) suspended | 設定の**不一致**などで外されている |
| (**I**) stand-alone | 相手と**ネゴシエーションできず**、1本のポートとして動いている |
| (**D**) down | リンクが落ちている |

- `show lacp neighbor`：相手の LACP の情報（相手が LACP を話しているか）
- `show etherchannel load-balance`：振り分け方

## 3. STP

### 何のための技術か

L2 のループは、ブロードキャストが**回り続けて増え**、ネットワーク全体を止める。STP は、ループになるリンクの**1か所をブロックして木の形にする**。

### Cisco の STP の種類

| 種類 | 標準 | 特徴 |
| --- | --- | --- |
| PVST+ | Cisco | **VLAN ごと**に STP の木を作る。昔の Cisco の既定 |
| **Rapid PVST+** | Cisco | **VLAN ごと**の RSTP。切替えが速い。**よく使われる** |
| RSTP | IEEE 802.1w | 速い STP。木は1つ |
| **MST** | IEEE 802.1s | **複数の VLAN をまとめたインスタンス**ごとに木を作る。VLAN が多くても木の数が少なくて済む |

### ルートブリッジとポートの決まり方

**ブリッジ ID ＝ 優先度 ＋ 拡張システム ID（VLAN 番号） ＋ MAC アドレス**。小さいほうが勝つ。

- 優先度の既定は **32768**。**4096 の倍数**でしか設定できない
- 拡張システム ID が足されるので、VLAN 10 の既定は **32778**（32768 ＋ 10）と表示される

| 決めるもの | 比べる順番 |
| --- | --- |
| ルートブリッジ | **ブリッジ ID が最小** |
| ルートポート（各スイッチに1つ） | ① ルートまでの**コストの合計が最小** → ② 相手のブリッジ ID が最小 → ③ 相手のポート ID が最小 |
| 指定ポート（各リンクに1つ） | そのリンクで、ルートまでのコストが最小のスイッチのポート |
| 残り | **代替ポート（Alternate）**・**バックアップポート**として**ブロック** |

| 帯域 | コスト（短い形式） |
| --- | --- |
| 10Mbps | 100 |
| 100Mbps | 19 |
| 1Gbps | 4 |
| 10Gbps | 2 |

RSTP のポートの状態は **Discarding・Learning・Forwarding** の3つ。**ポイントツーポイントのリンク**では、隣のスイッチと**提案と合意（proposal／agreement）**をやり取りして、タイマーを待たずにすぐ転送を始める。

### 設定例：Rapid PVST+ で VLAN ごとにルートを分ける

```
spanning-tree mode rapid-pvst
!
! SW1 で
spanning-tree vlan 10 root primary
spanning-tree vlan 20 root secondary
!
! SW2 で
spanning-tree vlan 20 root primary
spanning-tree vlan 10 root secondary
```

- `root primary` は優先度を **24576**（いまのルートがそれ以下なら、さらに 4096 小さい値）にする。`root secondary` は **28672**
- 直接 `spanning-tree vlan 10 priority 4096` と値を書いてもよい
- VLAN 10 は SW1、VLAN 20 は SW2 をルートにすると、**VLAN ごとにブロックされるリンクが変わり、両方のリンクを使える**（負荷分散）
- ポート単位で経路を調整するときは、インタフェースで `spanning-tree vlan 10 cost 10` や `spanning-tree vlan 10 port-priority 64`

### 設定例：MST

```
spanning-tree mode mst
spanning-tree mst configuration
 name REGION1
 revision 1
 instance 1 vlan 10,20
 instance 2 vlan 30,40
!
spanning-tree mst 1 root primary
```

- **名前・リビジョン番号・VLAN とインスタンスの対応**が**すべて同じ**スイッチが、同じ **MST リージョン**になる。1つでも違うと別のリージョンになり、意図どおりに動かない
- どのインスタンスにも入れていない VLAN は、**インスタンス 0（IST）**に入る

- `show spanning-tree mst`：MST のインスタンスごとの状態
- `show spanning-tree summary`：モードや、保護機能が有効かどうか

## 4. STP の保護機能

```mermaid
flowchart LR
  D["ディストリ<br>（ルート）"] -- "ルートガード" --- A["アクセス<br>スイッチ"]
  A -- "PortFast<br>BPDU ガード" --- P["PC"]
```

| 機能 | 設定 | 動き | 置く場所 |
| --- | --- | --- | --- |
| **PortFast** | `spanning-tree portfast` | **すぐ転送を始める**（エッジポート） | **PC・サーバ用**のポート |
| **BPDU ガード** | `spanning-tree bpduguard enable` | BPDU を受け取ったら**ポートを止める（err-disabled）** | PortFast のポート |
| BPDU フィルタ | `spanning-tree bpdufilter enable` | BPDU を**送受信しない** | 使いどころは限られる（ループを見逃す危険） |
| **ルートガード** | `spanning-tree guard root` | より強い BPDU（ルートを奪おうとする BPDU）を受けたら、そのポートを**ブロック**（root-inconsistent）。届かなくなれば**自動で戻る** | ルートになってほしくない機器へ向かう**下向きのポート** |
| ループガード | `spanning-tree guard loop` | ルートポート・代替ポートで BPDU が**届かなくなっても、転送に切り替えない** | 上向きのポート（片方向だけ通じるリンクの対策） |

- まとめて有効にする：`spanning-tree portfast default`（アクセスポート全部）、`spanning-tree portfast bpduguard default`（PortFast のポート全部）
- **err-disabled** になったポートは、`shutdown` → `no shutdown` で戻す。自動で戻したいなら `errdisable recovery cause bpduguard`
- 止まっているポートは `show interfaces status err-disabled` で探せる

## 確認問題

<details>
<summary>1. 両端のポートを dynamic auto にした。トランクになるか</summary>

**ならない**（アクセスポートになる）。auto は「誘われたらトランクになる」だけで、どちらも自分からは誘わないから。片方を `dynamic desirable` か `trunk` にする。
</details>

<details>
<summary>2. トランクに VLAN 30 を足そうとして switchport trunk allowed vlan 30 と打った。何が起きるか</summary>

許可 VLAN が **30 だけに置き換わり**、それまで通っていた VLAN が通らなくなる。足すときは `switchport trunk allowed vlan add 30`。
</details>

<details>
<summary>3. show etherchannel summary で、メンバーのポートに (s) が付いている。何を疑うか</summary>

**suspended**（外されている）。メンバー間で**速度・デュプレックス・VLAN の設定（アクセス VLAN、ネイティブ VLAN、許可 VLAN）**が一致しているかを確かめる。
</details>

<details>
<summary>4. LACP で、両端を passive にした。束なるか</summary>

**束ならない**。passive はどちらも自分からネゴシエーションを始めないから。少なくとも片方を `active` にする。
</details>

<details>
<summary>5. VLAN 10 で、優先度を設定していないスイッチの show spanning-tree に表示される優先度はいくつか</summary>

**32778**。既定の 32768 に、拡張システム ID として VLAN 番号の 10 が足される。
</details>

<details>
<summary>6. PC 用のポートに BPDU ガードを設定する理由</summary>

利用者が**スイッチを勝手につなぐ**と、BPDU が届いてループや STP の再計算が起きるおそれがある。BPDU ガードは BPDU を受け取った時点で**ポートを止め**、それを防ぐ。
</details>

<details>
<summary>7. MST で、2台のスイッチを同じリージョンにするために一致させるものは何か</summary>

**リージョン名・リビジョン番号・VLAN とインスタンスの対応**の3つ。
</details>
